# Common SensorML fixture attribution

These original synthetic fixtures were authored for task 2.2.1 (#39), not copied
from a peer implementation or generated by the mapper under test. They exercise
the shared described-object boundary, not complete SimpleProcess/System family
validation, HTTP handling, registration authority or policy decisions.

The controlling schema snapshot is CSAPI commit
`8e03b236a049849f2ccc24b4fd9fdce5ff69bed2`, already packaged unchanged in
[`corpus/manifest.json`](../../corpus/manifest.json). Source rules are in
[`DescribedObject.json`](../../corpus/originals/csapi/sensorml/schemas/json/DescribedObject.json),
[`commonDefs.json#/$defs/Term`](../../corpus/originals/csapi/sensorml/schemas/json/commonDefs.json),
[`ResponsibleParty.json`](../../corpus/originals/csapi/sensorml/schemas/json/ResponsibleParty.json),
[`ContactLink.json`](../../corpus/originals/csapi/sensorml/schemas/json/ContactLink.json),
[`Document.json`](../../corpus/originals/csapi/sensorml/schemas/json/Document.json),
[`link.json`](../../corpus/originals/csapi/common/link.json) and
[`timePeriod.json`](../../corpus/originals/csapi/common/timePeriod.json).
Guide sections 4.2, 4.3 and 4.10 additionally require separate source evidence,
preserved identities/extensions and no promotion of descriptive contacts into
authenticated identity or external link retrieval.

The independent expected-field table is deliberately discriminating:

| Field | Expected meaning/value |
|---|---|
| `id` / `uniqueId` | `local-A` / `urn:example:sensor:alpha`; not the nested extension's `id` |
| `label` | ` Alpha sensor `, including spaces |
| `identifiers` | Two values `000042` remain separate, in supplied order, with manufacturer-a and operator-b code spaces |
| `classifiers[0]` | `sensor-kind` definition, `local` code space and `thermometer` value |
| `contacts[0]` | Individual Synthetic Operator, custodian role and every phone/address/contact field |
| `contacts[1]` | Linked Synthetic Manufacturer with exact URI, role and all supplied link metadata |
| `documents[0]` | Calibration report A, exact PDF link, role, description and UID |
| `validTime` | Two distinct nanosecond-precision October endpoints; not ingestion time |
| `ex:calibration` | Exact object including integer 9007199254740993, false, null and uninterpreted nested identity/contact names |
| `additionalInfo` | Open descriptive member retained, without claiming family-specific semantics |
| Source evidence | Exact input bytes/media type/SHA-256, independent of newly generated JSON |

Tests compare general JSON fields against authored constants before any
production-type interpretation. A reordered input has the same descriptive
meaning but different retained bytes and digest. Disposable wrong-output values
drop a contact, remove an extension or replace an identifier to prove that the
same oracle rejects those mistakes. The executable no-fetch test replaces links
with a controlled loopback listener and verifies no connection is accepted;
the `.invalid` fixture addresses alone are not claimed as that proof.
