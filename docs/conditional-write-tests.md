# Conditional System write: independently specified checks

Issue [#16](https://github.com/DGIWG-P507/glaux-server/issues/16) implements the
internal revision-condition boundary of Guide v1.21 §§4.6, 6.4 and 8.1.1.
This truth table precedes its production implementation. Execution is not yet
claimed. The boundary is not an HTTP ETag parser or a complete PUT/PATCH API.

## Fixed facts and expected outcomes

Use fixed UUIDv7-shaped identities with prefix
`01890f20-7b5a-7cc3-98c4-dc0c0c08`: parent `0101`, child `0102`, missing `0199`.
The child has UID `urn:glaux:test:conditional-child`, source alias
(`urn:glaux:test:conditional-source`, `upstream-child`), and parent `0101`.
Updates never change those facts. Revision/artifact/audit/work suffixes are,
respectively, `0301/0201/0401/0501` for the original, `0302/0202/0402/0502`
for A, and `0303/0203/0403/0503` for B. Their labels and original opaque bytes
are respectively `Original`/`original-bytes`, `Writer A`/`writer-A-bytes` and
`Writer B`/`writer-B-bytes`. Those bytes are independently authored and are not
generated by a production serializer. They make no SensorML-validity claim.

The exact recorded time is
`2017-01-01T01:00:00.12345678901234567890+01:00`: civil second `1483228800`,
fraction `0.12345678901234567890`, not a leap second. Exact source spelling,
bytes and retained revision references are checked through raw SQL.

| Case | Expected result | Wrong behavior detected |
|---|---|---|
| Supplied original revision, no competing write | A commits label, source bytes, revision, accepted update audit, outgoing update and current head together; original facts remain unchanged | Comparing an unrelated or invented revision; incomplete accepted update |
| Supplied original revision after A committed | Distinct `PreconditionFailed`; every table value equals the preceding snapshot | Ignoring the condition; returning a generic conflict; side effects before rejection |
| Missing condition after A committed | B commits normally and becomes the head, while A and original remain retained | Mandatory-condition policy not selected by the Guide |
| Missing resource / existing low-level System without an authoritative head | Respectively `NotFound` / `UninitializedRevision`, with no mutation | Accidental upsert; inventing current revision from ID/time ordering |
| Invalid revision association, artifact binding, metadata or ambient transaction | Safe explicit rejection and unchanged complete state | Cross-System association or partial write |
| Two conditional writers, A then B and B then A | Actual database lock wait is observed; first commits, waiter rereads the newly committed head and fails; exact winning value and original/winner history remain | Check-before-lock, stale transaction snapshot, race permitting both writers |
| Conditional winner, unconditional stale waiter | Waiter is allowed to overwrite after the winner; both accepted revisions are retained | Claiming row locking detects stale clients that supplied no condition |
| Writer blocked at final database boundary | Separate observer sees the complete old snapshot, then complete new facts after release | Partial visibility or successful response before commit |
| Failure after each update-side write and at deferred commit | Complete snapshot unchanged, including current head, prior history, audit, outgoing work and coordination row | Independent commits, missing rollback, early head advance |
| Migration from schema 6 with accepted creation and a newer unattached revision | Head selects the creation justified by the accepted creation work/audit, never highest revision ID/time | Guessing current state from retained history |
| Ambiguous old accepted creations for one System | Migration fails atomically rather than choosing a winner | Silent arbitrary backfill |
| Controlled omission of comparison from a passing baseline | Exact stale-condition assertion fails; setup/compiler/cleanup failures do not count | A nominal race test that cannot detect missing condition enforcement |

Snapshots cover ordered values of every affected table, not counts alone.
Concurrency uses separate real SQLx connections, explicit test-owned database
barriers, observed backend lock waits and bounded timeouts; no sleep establishes
ordering. Both competing orderings use distinct predetermined payloads.

The new checks run only in the existing GitHub-hosted Linux, owned isolated
PostgreSQL/PostGIS harness. No caller-selected target, operational data,
additional service or company-laptop runtime is used. The real source remains
unchanged during disposable fault controls. Cleanup/setup failures are fatal.

Remaining work includes HTTP representation-specific validators, authentication
and authorization, full family-specific writable projections, retry records,
external delivery, recovery and retention. Internal revision IDs are not a
substitute for the Guide's authorized-view, representation-specific HTTP tags.
